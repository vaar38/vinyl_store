# Магазин виниловых пластинок

Учебный проект по предмету «Создание программного обеспечения».

**Тема** — «Разработка интернет-магазина виниловых пластинок с учётом остатков и оформлением заказов с доставкой».

В магазине будут продаваться только новые виниловые пластинки. В первой версии планируется 8–12 позиций. Заказы доставляются по указанному адресу, оплата при получении.



| Роль | Возможности |
| --- | --- |
| Гость | Просматривать каталог и карточки пластинок. |
| Покупатель | Работать с корзиной, оформлять заказы, смотреть их в личном кабинете и отменять до отправки. |
| Сотрудник магазина | Собирать заказы, передавать их в доставку и отмечать получение. |
| Администратор | Управлять товарами, ценами и остатками. |

В карточке пластинки отображаются обложка, исполнитель, альбом, жанр, цена и доступный остаток.

## Остатки и заказы

- Добавление пластинки в корзину не меняет доступный остаток.
- При оформлении сервер в одной транзакции проверяет и уменьшает доступный остаток, создаёт заказ и фиксирует цену в каждой позиции. Если хотя бы одной позиции не хватает, транзакция откатывается целиком.
- Если два покупателя одновременно оформляют последнюю пластинку, один заказ создаётся, а второй запрос получает HTTP `409 Conflict`.
- Покупатель может отменить заказ до отправки. Отмена и возврат зарезервированного количества в доступный остаток выполняются в одной транзакции.
- При отправке и доставке заказа доступный остаток повторно не уменьшается.
- Изменения остатков записываются в журнал движений, а переходы заказа — в историю статусов. Записи сохраняются в той же транзакции, что и соответствующие изменения.

В заказе сохраняются имя и телефон получателя, адрес и комментарий к доставке, её стоимость и итоговая сумма. Изменение профиля покупателя не меняет данные оформленного заказа.

## Состояние проекта

Реализован учебный MVP магазина с доставкой и оплатой при получении.

## Запуск фронтенда

Требуется Node.js 20.19+ или 22.12+. В одном терминале запустите FastAPI из папки `backend`:

```powershell
python -m uvicorn app.main:app --reload
```

В другом терминале из папки `frontend` установите зависимости и запустите интерфейс:

```powershell
npm install
npm run dev
```

Откройте http://127.0.0.1:5173. Vite перенаправляет запросы `/api` на FastAPI по адресу http://127.0.0.1:8000. Для запуска API требуется настроенный `backend/.env` и применённые миграции.

Интерфейс поддерживает каталог, поиск по названию, фильтр жанров, карточку пластинки, регистрацию, вход, профиль, корзину и оформление заказа с доставкой и оплатой при получении.

Проверка производственной сборки из папки `frontend`:

```powershell
npm run build
```

## Готовые возможности

Каталог с поиском по альбому и фильтром жанров, карточки пластинок, регистрация и вход по JWT, профиль, корзина, оформление заказа, список и подробности своих заказов, отмена до отправки. Доставка бесплатная, оплата при получении.

Сотрудник видит все заказы и проводит их по статусам `created → assembling → ready → shipped → delivered`. Отмена покупателем возможна из `created`, `assembling` и `ready`. Повторная отмена не возвращает остатки второй раз.

Администратор создаёт и редактирует пластинки, исполнителей и жанры, меняет цены и доступные остатки, скрывает товары. Ручные изменения остатков записываются в `stock_movements`. Если карточка изменилась после открытия формы, сохранение отклоняется с `409`, чтобы устаревшая правка не восстановила уже зарезервированные экземпляры.

## Роли и служебные аккаунты

Новые покупатели получают роль `customer`. Для подготовки ролей при локальном запуске выполните из `backend`:

```powershell
python -m app.bootstrap
```

Первый аккаунт администратора создаётся отдельной командой. Пароль вводится скрыто в терминале:

```powershell
python -m app.bootstrap --email admin@example.com --role admin --name "Администратор"
```

Для сотрудника используйте другой email и `--role staff`. Войдите с этим аккаунтом в интерфейсе. В разделе аккаунта появится управление каталогом или рабочее место сотрудника. Обычная регистрация всегда создаёт покупателя.

## Запуск в Docker

Требуется работающий Docker Desktop с Linux-контейнерами. Из корня проекта скопируйте `.env.example` в `.env`, задайте собственный пароль базы и случайный `SECRET_KEY`. Пример генерации ключа:

```powershell
python -c "import secrets; print(secrets.token_hex(32))"
docker compose up -d --build
```

Магазин откроется на http://localhost:8080, Swagger — http://localhost:8080/docs. Прямой адрес Swagger бэкенда внутри сети контейнеров — `/docs`; Nginx публикует его по указанному адресу. Миграции и создание ролей выполняются при старте бэкенда. Первый администратор создаётся так:

```powershell
docker compose exec backend python -m app.bootstrap --email admin@example.com --role admin --name "Администратор"
```

Остановка — `docker compose down`. Данные PostgreSQL сохраняются в томе `postgres_data`. Локальная база из `backend/.env` и контейнерная база — отдельные хранилища.

## Тесты

Набор содержит 22 теста API и 7 сценариев интерфейса. Каждый UI-сценарий выполняется на двух размерах экрана: всего 29 уникальных тест-кейсов и 36 проверок при полном прогоне.

Тесты API используют настоящий PostgreSQL. Каждый тест создаёт отдельную схему с уникальным именем и удаляет её после завершения. Требуется пользователь базы с правом создания схем. Запуск из `backend` в активированном окружении:

```powershell
uv pip install -r requirements-dev.txt
python -m pytest -q tests
```

Запуск в контейнере:

```powershell
docker compose exec backend python -m pytest -q tests
```

| Сценарий | Ожидаемый результат |
| --- | --- |
| Регистрация и повторный email | `201`, затем `409` |
| Вход с неверным паролем, просроченный JWT | `401` |
| Скрытая пластинка | `404` в карточке и при добавлении |
| Чужая корзина и заказ | Нет доступа к чужим данным |
| Одновременные добавления в корзину | Количество складывается, корзина одна |
| Оформление с нехваткой одной позиции | `409`, весь резерв и заказ откатываются |
| Два покупателя последней пластинки | Один `201`, второй `409`, остаток `0` |
| Изменение цены после заказа | Цена позиции заказа сохраняется |
| Повторная и одновременная отмена | Остаток возвращается один раз |
| Одновременная отмена и отправка | Успешно только одно действие |
| Доступ покупателя к админке | `403` |
| Устаревшая правка администратором | `409`, резерв сохраняется |


## Локальный бэкенд с нуля

Создайте PostgreSQL-базу `vinyl_store`. Из корня проекта в PowerShell:

```powershell
uv venv --python 3.12
.\.venv\Scripts\Activate.ps1
uv pip install -r backend/requirements-dev.txt
Copy-Item backend/.env.example backend/.env
```

Укажите свои данные в `backend/.env`. В пароле внутри `DATABASE_URL` символ `@` записывается как `%40`. Задайте случайный `SECRET_KEY`. Затем:

```powershell
cd backend
python -m alembic upgrade head
python -m app.bootstrap
python -m uvicorn app.main:app --reload
```

При повторном запуске используйте существующее окружение и `.env`. Swagger доступен на http://127.0.0.1:8000/docs.

## Браузерные тесты

Из папки `frontend`:

```powershell
npm install
npx playwright install chromium
npm run test:e2e
```

Тесты сами запускают Vite и проверяют интерфейс на десктопном и мобильном размерах. Ответы API в этих тестах подставляются, чтобы проверить интерфейс независимо от наполнения базы. Операции, права и конкурентные транзакции на PostgreSQL проверяет `backend/tests/test_shop.py`. На Windows можно использовать установленный Edge: `$env:PLAYWRIGHT_CHANNEL = 'msedge'` перед запуском тестов.

## Проверка Python-кода

Из `backend` выполните `python -m flake8 app --max-line-length=100`. Обработчики используют общую сессию запроса. При исключении транзакция откатывается, соединение возвращается в пул.
